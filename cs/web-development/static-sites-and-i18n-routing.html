🌐Static sites and multilingual (i18n) routing

Build every page in advance, one copy per language, and send each visitor to the right one.

beginnercs2026-11-27example: portfolio

💡The idea

A web page can be made at three moments. A static page is built once, before anyone visits. A server-rendered page is built by a server each time someone asks. A client-rendered page is built by JavaScript inside the visitor's browser. For a site in several languages, the static way is simple: build one finished page per language, give each its own address (/en, /fr), and send each visitor to the right one.

💡 Think of it like this

A static page is a printed leaflet: copies wait in a stack, you just hand one out. A server-rendered page is a meal cooked to order. A client-rendered page is a flat-pack kit the visitor builds at home. A bilingual site is two stacks of leaflets, one per language.

📖Key words

CDN
A "content delivery network": many servers around the world that keep copies of your files, so each visitor downloads from a nearby one.
i18n
Short for "internationalisation" (i + 18 letters + n): making a site work in several languages.
Accept-Language
A line the browser sends with every request, listing the languages its user prefers, each with a score called a q-value (0 to 1).
Cookie
A small note a site stores in your browser; the browser sends it back on every later visit.
hreflang
Links in the page that tell search engines "this same page exists in French, at this address".

⚙️How it works

  1. Build: the framework makes one HTML file per language and page (/en, /fr, /en/how-its-built…). Any other language code gives a 404 (page not found).
  2. Text from dictionaries: all words live in one list per language, so each build just swaps the list.
  3. Visitor opens /: a small piece of code in front of the site picks a language. First choice: the lang cookie. Otherwise: the best match in Accept-Language. Then it redirects (sends the browser to another address).
  4. Visitor opens /fr: the static page is sent and the cookie is set to fr, so the choice is remembered.
  5. Label the page: <html lang="fr"> tells screen readers and translators the language; hreflang links point search engines to the other versions.
⚠️ Common mistake

Don't rely only on auto-detection. Someone in France may prefer English. Always give a visible language switch, and let the URL be the final word.

🔍Example

In the portfolio, this decision lives in the proxy (Next.js 16's name for middleware: code that runs before a page is sent). Shortened:

// URL already has a language: let it through, remember it
if (isLocale(first)) {
  const response = NextResponse.next();
  response.cookies.set("lang", first, { path: "/", maxAge: YEAR });
  return response;
}
// No language in URL: cookie first, else the browser's list
const saved = request.cookies.get("lang")?.value;
const lang = saved && isLocale(saved)
  ? saved
  : localeFromAcceptLanguage(request.headers.get("accept-language"));
url.pathname = `/${lang}${pathname === "/" ? "" : pathname}`;
return NextResponse.redirect(url);

A browser sends de-DE,de;q=0.9,fr;q=0.8,en;q=0.7. No q-value means 1. Sorted: German 1, German 0.9, French 0.8, English 0.7. The site has no German, so the first supported one wins:

⚖️Why use it

✅ Advantages

  • Very fast and cheap: a CDN just hands out ready files.
  • One URL per language can be shared, bookmarked and found by search engines.
  • Visitors land in their language without doing anything.

⚠️ Limits

  • Content that changes per user or every minute can't be fully static.
  • Each new language multiplies the number of pages to build.

🔀Other ways

Same URL, auto-detected language: simpler addresses, but links can't be shared per language and search engines see only one version.
Subdomains (fr.site.com): one host per language, same idea as /fr.
Client-side translation: one page that swaps text with JavaScript; slower first view and bad for search engines.

🎯Quiz

  1. A page built once in advance and sent as the same file to every visitor is called a _____ page.

    Answer

    Static. It is made before anyone visits, so the server only has to hand out a ready file.

  2. Which kind of page is built by the server at the moment each visitor asks for it?

    1. Static
    2. Server-rendered
    3. Client-rendered
    4. Cached
    Answer

    B. Server-rendered pages are made fresh for each request. C is tempting, but client-rendered pages are built in the browser, not on the server.

  3. Why does a static page usually load faster than a server-rendered one?

    Answer

    It is already built, so nothing has to be computed, and a CDN keeps copies near each visitor, so the file travels a short distance.

  4. Is it true that a CDN is a single big server that all visitors connect to?

    Answer

    No, false. A CDN is many servers spread around the world, each with a copy of the files, so visitors use a nearby one.

  5. Making a website work in several languages is called internationalisation, shortened to _____.

    Answer

    i18n. There are 18 letters between the "i" and the "n" of "internationalisation".

  6. Why is it useful to give each language its own URL, such as /en and /fr?

    Answer

    Each version can be shared, bookmarked and indexed by search engines, and each can be a ready-made static page.

  7. Is it true that automatic language detection means the site no longer needs a language switch?

    Answer

    No, false. Detection is only a guess from browser settings. Users still need a visible way to pick another language.

  8. Is it true that in Accept-Language, a language written without a q-value counts as the top preference?

    Answer

    Yes, true. A missing q-value means q=1, the highest score.

  9. A browser sends "fr, en;q=0.9, de;q=0.5" to a site with only English and German. Which language should it get?

    1. French
    2. German
    3. English
    4. None: show an error
    Answer

    C. French scores highest but the site doesn't have it, so the next best supported language wins: English (0.9) beats German (0.5).

  10. Why does a multilingual site save the visitor's language choice in a cookie?

    Answer

    The browser sends the cookie back on every visit, so the site remembers the choice next time, even if the browser's languages say something else.

  11. What does the lang attribute on the <html> tag tell?

    1. Which programming language the server uses
    2. Which languages the visitor speaks
    3. Which other translations exist
    4. The language the page's text is written in
    Answer

    D. It labels the page's language for screen readers, translators and search engines. C is tempting, but that is the job of hreflang links.

  12. Links that tell search engines "this page also exists in another language, here" use the attribute _____.

    Answer

    hreflang. Each link gives a language code and the address of that version, so search results show the right one.

🔎Things worth noticing

  • The pages are static, but the redirect on / still needs a tiny bit of server code (the proxy). A pure static export with no server could not do it.
  • The cookie is set whenever someone opens /fr, even from a shared link. Clicking a French link changes the remembered language. That's a design choice, not a bug.
  • hreflang links must be full addresses (https://…/fr), which is why the layout sets metadataBase. An x-default link names the page for everyone else (English here).
