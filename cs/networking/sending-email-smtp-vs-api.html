📧How programs send email: SMTP vs HTTP email APIs

A program can talk to a mail server directly with SMTP, or ask an email service to do it through a normal web request.

beginnercs2026-11-27

💡The idea

Email travels with SMTP, an old set of rules for handing a message to a mail server. A program can speak SMTP itself: connect to a server like Gmail, log in, and hand over the message. Or it can call an HTTP email API: send one ordinary web request to an email company, which speaks SMTP for you. Both end in the same inbox. The difference is which door your program knocks on, and some hosting providers lock the SMTP door.

💡 Think of it like this

SMTP is walking to the post office yourself. An HTTP email API is handing your letter to a courier at your front door. If the road to the post office is closed, the courier still gets through.

📖Key words

SMTP
Simple Mail Transfer Protocol: the standard rules for sending email to a mail server.
Port
A numbered door on a server; each kind of traffic uses its own number.
TLS
Encryption that stops anyone in the middle from reading the connection (the "S" in HTTPS).
App password
A separate password made for one program, so your real password never leaves your hands.
HTTP email API
An email service you call with a web request and an API key (a secret token that proves who you are).

⚙️How it works

  1. Find the server. DNS (the internet's phone book) turns smtp.gmail.com into addresses: a short IPv4 one and a long, newer IPv6 one. If your machine has no IPv6 route, trying IPv6 fails with "Network is unreachable". Asking for IPv4 only avoids that.
  2. Open a door. Connect to port 587 or 465.
  3. Encrypt. On 587 the talk starts in plain text, then the STARTTLS command switches on encryption. On 465 it is implicit TLS: encrypted from the first byte.
  4. Log in with an app password (Gmail requires 2-step verification for this).
  5. Hand over the message with its headers: From, To, Subject and Reply-To (where the "Reply" button sends the answer).
⚠️ Why hosts block SMTP

Spammers love free servers. So many cloud hosts (like Render's free plan) block outgoing ports 25, 465 and 587. No code change can fix that; only a different road can.

🔍Example

Your portfolio's contact form, simplified. Way 1 failed on Render; way 2 works because it looks like any web request.

# Way 1: SMTP (blocked on Render's free plan)
with SMTP4(host, 587, timeout=10) as smtp:  # IPv4-only connection
    smtp.starttls(context=context)          # switch on encryption
    smtp.login(user, app_password)          # never the real password
    smtp.send_message(msg)                  # From, To, Reply-To, Subject

# Way 2: HTTP API (plain HTTPS on port 443)
httpx.post(
    "https://api.resend.com/emails",
    json={"from": sender, "to": [my_inbox], "reply_to": visitor,
          "subject": subject, "text": body},
    headers={"Authorization": f"Bearer {api_key}"},
    timeout=10,
)

With reply_to set to the visitor, pressing "Reply" in Gmail answers them directly.

⚖️Why use it

✅ HTTP email API

  • Works wherever the web works (port 443).
  • One request; the service handles retries and spam reputation.

⚠️ Trade-offs

  • You depend on a company, its free limits and an API key to protect.
  • SMTP is a universal standard; an API is specific to one provider.

🔀Other ways

Paid hosting plan: many hosts unblock SMTP ports for paying users.
Other email APIs: SendGrid, Mailgun or Postmark work the same way as Resend.
Form services: a ready-made form backend emails you without any server code.

🎯Quiz

  1. The standard protocol used to send email to a mail server is called _____.

    Answer

    SMTP. Simple Mail Transfer Protocol is the set of rules every mail server understands for receiving messages.

  2. Which port is mainly used for email passed between mail servers?

    1. 443
    2. 587
    3. 80
    4. 25
    Answer

    D. Port 25 is the server-to-server door. B is tempting, but 587 is for programs that log in to submit mail.

  3. Is it true that port 587 encrypts the connection from the very first byte?

    Answer

    No, false. On 587 the conversation starts in plain text and STARTTLS switches on encryption. Encryption from the first byte is port 465 (implicit TLS).

  4. What is the difference between STARTTLS and implicit TLS?

    Answer

    STARTTLS starts unencrypted, then upgrades the same connection to encryption. Implicit TLS is encrypted from the start. Both encrypt before the password is sent.

  5. Is it true that an app password is just your normal account password typed into a program?

    Answer

    No, false. It is a separate password created for one program. Your real password stays private.

  6. Why is an app password safer than putting your real password in a program?

    Answer

    If it leaks, you delete just that app password. Your real password and your 2-step verification stay safe, and the rest of your account is protected.

  7. Besides the older IPv4 address, a server name can also resolve to a newer _____ address.

    Answer

    IPv6. DNS can return both kinds. A program may try IPv6 first, even if the machine cannot reach IPv6.

  8. A server has no IPv6 route, and a program tries the IPv6 address first. What happens?

    1. The connection fails with "Network is unreachable"
    2. The email is sent, only more slowly
    3. The DNS lookup fails
    4. The mail server rejects the password
    Answer

    A. There is no path to any IPv6 address, so the connection cannot even start. Forcing IPv4 avoids this. D is wrong because the program never reaches the login step.

  9. Why do many cloud hosts block outgoing SMTP ports on their free plans?

    1. SMTP is too slow for their servers
    2. SMTP only works on home computers
    3. To stop people using free servers to send spam
    4. To force programs to use IPv6
    Answer

    C. Free servers are easy for spammers to abuse, which harms the host's reputation. A is tempting, but speed has nothing to do with it.

  10. What does a program send to prove who it is when it calls an HTTP email API?

    1. Its IPv4 address
    2. An API key in a request header
    3. The visitor's email address
    4. An SMTP app password
    Answer

    B. The API key is a secret token, usually sent in the Authorization header. D is tempting, but app passwords are for SMTP logins.

  11. Is it true that an HTTP email API can still deliver to normal inboxes like Gmail?

    Answer

    Yes, true. The service receives your request, then sends the email with SMTP from its own servers, so it lands in any inbox.

  12. Why does an HTTP email API work on a host that blocks SMTP?

    Answer

    It uses HTTPS on port 443, the same door as all web traffic, which hosts do not block. The SMTP part happens on the email service's servers, not yours.

  13. Is it true that the Reply-To header decides who receives the email?

    Answer

    No, false. The To header decides who receives it. Reply-To only decides where the answer goes when the reader presses "Reply".

🔎Things worth noticing

  • The "Network is unreachable" error may have hidden the real cause. Python tries each address in turn and reports only the last failure, so the IPv4 attempt might already have been blocked. Forcing IPv4 is still harmless.
  • Resend's test sender (onboarding@resend.dev) can only send to the address you signed up with. That is fine for a contact form that mails you.
  • The code keeps SMTP as a fallback, so it still works on hosts or computers where port 587 is open.
