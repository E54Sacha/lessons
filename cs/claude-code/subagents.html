🤖Claude Code subagents

Helper Claudes that do one job on their own, then hand back a short report.

beginnercs2026-11-26example: claude-dev-toolkit

💡The idea

A subagent is a helper assistant that the main Claude can hand a job to. Each subagent has its own instructions, its own allowed tools and its own memory. This keeps the main conversation tidy and makes sure some jobs are always done the same way.

💡 Think of it like this

A manager gives one task to a specialist colleague. The specialist works alone at their own desk, then hands back a short report. The manager never sees the messy notes.

📖Key words

Subagent
A separate Claude with its own role, started by the main Claude to do one task.
Frontmatter
The block between the two --- lines at the top of the file, holding settings like name and tools.
Description
A sentence that tells the main Claude when to call this subagent.
System prompt
The text under the frontmatter: the subagent's permanent job description.
Context window
The "working memory" of one conversation. A subagent starts with a fresh, empty one.

⚙️How it works

  1. You write a Markdown file: frontmatter on top, instructions below.
  2. Claude Code reads the name and description of every subagent when it starts.
  3. When your request matches a description, the main Claude delegates the task to that subagent.
  4. The subagent starts fresh: it only sees its system prompt and the task message, not your whole chat.
  5. It works using only the tools it is allowed, then sends one final report back.
  6. The main Claude reads that report and continues talking with you.

🔍Example

The tutor subagent writes beginner lessons like this one. Its description lists phrases like "explain this", so the main Claude knows when to call it. It may only read, search and write files, so it cannot run commands.

---
name: tutor                      # how the subagent is identified
description: Teaches a beginner any topic ... Use when the user
  asks to explain, teach, or walk through code ...   # when to call it
tools: Read, Grep, Glob, Write   # only these tools, no shell commands
---

You are a patient tutor for a beginner student ...
                                 # system prompt starts here
⚠️ Common mistake

Assuming the subagent knows what you said earlier. It doesn't: put every detail it needs in the task message.

⚖️Why use it

✅ Advantages

  • The main conversation stays clean: the subagent's file reading stays in its own memory.
  • A specialist job is done the same way every time, with the same rules.
  • Limiting tools makes it safer: a helper that can't run commands can't break much.

⚠️ Limits

  • The subagent doesn't see your earlier chat, so the task message must contain everything.
  • A vague description means it may be called at the wrong time, or never.

🔀Other ways

Skill: when you want extra instructions loaded into the main conversation instead of a separate helper.
Just asking the main Claude: fine for a quick one-off task that needs no special rules.

🎯Quiz

  1. What is a subagent in Claude Code?

    Answer

    A separate Claude with its own role, instructions and tools, that the main Claude can hand one task to.

  2. A subagent's settings, like its name and tools, go in the _____, the block between the two --- lines.

    Answer

    Frontmatter. It holds the settings; the instructions come after it.

  3. How does the main Claude decide which subagent to call?

    1. It always calls the first subagent in the folder
    2. It asks you to pick one every time
    3. It compares your request with each subagent's description
    4. It calls every subagent and keeps the best answer
    Answer

    C. The description says when to use the subagent. D is tempting, but calling every subagent would waste time and mix results.

  4. Is it true that Claude still calls a subagent at the right moments, even if its description is vague?

    Answer

    No, false. A vague description makes Claude call it for the wrong tasks, or not call it at all.

  5. The instructions under the frontmatter are called the subagent's _____ prompt.

    Answer

    System. It's the subagent's permanent job description, used every time it runs.

  6. Why does a subagent start with an empty context window?

    Answer

    So it isn't cluttered by the main chat, and its own work (like reading many files) doesn't fill up the main conversation.

  7. Is it true that a subagent can see everything you said earlier in your chat with the main Claude?

    Answer

    No, false. It only sees its system prompt and the task message, so the task message must contain every detail it needs.

  8. Why would you limit the tools a subagent can use?

    1. For safety and focus: it can only do what its job needs
    2. Because subagents can't use more than four tools
    3. To make its answers longer
    4. Tools only work in the main conversation
    Answer

    A. A helper that can only read files can't accidentally run a dangerous command. B is wrong: there's no four-tool limit.

  9. Is it true that a subagent sends one final report back to the main Claude when it finishes?

    Answer

    Yes, true. The main Claude reads that report, then continues talking with you.

🔎Things worth noticing

The tutor's instructions say "write only inside the lessons repo", but the Write tool itself can write anywhere. That limit is a written rule, not a technical lock.
