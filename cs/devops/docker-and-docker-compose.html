🐳Docker and Docker Compose

Run programs like a database in sealed boxes that behave the same on your PC, in CI and in production.

beginnercs2026-11-27

💡The idea

Docker runs programs inside containers: sealed boxes that carry the program and everything it needs. A container is started from an image, a read-only package of files. Because the image is identical everywhere, Postgres 17 on your PC is exactly the same Postgres 17 in GitHub Actions and in production. Docker Compose lets you describe your containers in one file and start them with one command.

💡 Think of it like this

An image is a recipe. A container is a dish cooked from it. You can cook the same recipe many times, and throwing away a dish does not destroy the recipe.

Containers share a Linux kernel (the core of the operating system), so Windows needs a Linux to lend them. Docker Desktop uses WSL 2 for this, which is a real virtual machine. It needs hardware virtualization: if it is off, you get "WSL 2 can't start because virtualization isn't enabled". wsl --install --no-distribution installs the Windows parts of WSL without a Linux distribution, and a restart turns them on.

📖Key words

Image
A read-only package with a program and its files, named like postgres:17 (name:tag).
Container
A running copy of an image, isolated from the rest of your computer.
Volume
Storage kept by Docker outside the container, so data survives when the container is deleted.
Port mapping
A door from your PC into the container: 5432:5432 means "PC port : container port".
Healthcheck
A small command Docker repeats to know if the program inside is really ready.

⚙️How it works

  1. docker compose up -d reads the compose file, downloads the image if needed and starts the container in the background (-d = detached). Add --wait to return only once the healthcheck says "healthy".
  2. On the very first start, the volume is empty: Postgres creates its database and runs any scripts in /docker-entrypoint-initdb.d.
  3. docker compose ps shows what runs; docker compose logs db shows its output.
  4. docker compose exec db psql -U habits runs psql inside the running container.
  5. docker compose down deletes the container but keeps the volume. down -v also deletes the volume, so all the data is gone.
⚠️ Common mistake

Using down -v "to restart cleanly" when you meant down. The -v wipes your data. It is useful only when you want a fresh database, for example to rerun an init script.

🔍Example

The habit-tracker's docker-compose.yml (slightly shortened). Its init script holds one line, CREATE DATABASE habits_test OWNER habits;, which creates the database the tests use.

services:
  db:
    image: postgres:17              # recipe name:tag, pins the version
    environment:                    # settings read on the first start
      POSTGRES_USER: habits
      POSTGRES_PASSWORD: habits
      POSTGRES_DB: habits
    ports: ["5432:5432"]            # PC port : container port
    volumes:
      - db-data:/var/lib/postgresql/data              # data survives
      - ./api/db-init:/docker-entrypoint-initdb.d:ro  # init scripts, read-only
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U habits"]     # every 2 s, 15 tries
volumes:
  db-data:                          # the named volume

In CI, GitHub Actions starts the same image as a service container next to the test job: same postgres:17, same user, same port, same pg_isready healthcheck. The tests connect to localhost:5432 in both places, so they never notice the difference.

The API gets its own Dockerfile: a recipe for building your own image. Each instruction (copy files, install packages…) adds a layer. Docker caches layers, so a rebuild only redoes the layers that changed.

⚖️Why use it

✅ Advantages

  • Same version everywhere: PC, CI, production.
  • Nothing installed on Windows itself; delete the container and it is gone.
  • The whole setup lives in one file, shared with the code in Git.

⚠️ Limits

  • On Windows it needs WSL 2, virtualization and some RAM.
  • Data lives in volumes: easy to delete by mistake with -v.

🔀Other ways

Install Postgres on Windows: works, but versions drift between machines and it runs all the time.
A hosted database: a cloud provider runs Postgres for you; needs internet and an account.
Podman: another container tool that runs the same images.

🎯Quiz

  1. A running copy of a Docker image is called a _____.

    Answer

    Container. The image is the recipe; the container is the dish cooked from it, actually running.

  2. What is a Docker image?

    1. A program that is currently running
    2. A read-only package with a program and everything it needs
    3. A virtual machine with Windows inside
    4. A backup copy of your database data
    Answer

    B. An image is a read-only template used to start containers. A is tempting, but the running thing is the container, not the image.

  3. Is it true that you can start several containers from the same image?

    Answer

    Yes, true. Like cooking one recipe many times, each container is a separate running copy of the same image.

  4. In an image name like postgres:17, the part after the colon is called the _____.

    Answer

    Tag. The tag picks the version, so everyone who uses the same tag gets the same Postgres major version.

  5. Why run a database in a container instead of installing it directly on Windows?

    Answer

    Because the same image gives exactly the same version and settings on your PC, in CI and in production, and nothing gets installed on Windows itself. Delete the container and your system is clean again.

  6. Is it true that Docker Desktop runs Linux containers directly on the Windows kernel?

    Answer

    No, false. Linux containers need a Linux kernel. Docker Desktop runs them inside a small Linux virtual machine provided by WSL 2.

  7. Why can Docker Desktop fail with "virtualization isn't enabled"?

    1. You are not logged in to Docker Hub
    2. The image tag does not exist
    3. WSL 2 runs a virtual machine, which needs hardware virtualization turned on
    4. Port 5432 is already used by another program
    Answer

    C. WSL 2 is a real virtual machine, so the CPU's virtualization and the Windows virtual machine feature must be on. The other problems give different errors, after Docker has started.

  8. In a port mapping like 8080:80, the first number is the port on your _____.

    Answer

    Computer (the host). The format is "host port : container port": traffic to port 8080 on your PC goes to port 80 inside the container.

  9. Is it true that data written inside a container survives when the container is deleted, even without a volume?

    Answer

    No, false. Without a volume, the data lives in the container and is deleted with it. A volume stores it outside, so a new container finds it again.

  10. Why might the official Postgres image ignore your setup script the second time the database starts?

    Answer

    Because init scripts run only when the data volume is empty. On later starts the database already exists, so the scripts are skipped. To rerun them you must delete the volume.

  11. What does a healthcheck tell Docker?

    1. Whether the image has finished downloading
    2. How much memory the container uses
    3. Whether the volume is empty
    4. Whether the program inside is actually ready to work
    Answer

    D. A healthcheck repeats a small test (like pg_isready) until it passes. A container can be "running" before the program inside is ready, which is why A or a simple "started" is not enough.

  12. Why wait for the database to be healthy before running the tests?

    Answer

    Because the database needs a few seconds to start after the container starts. Tests run too early would fail to connect. --wait or a healthcheck in CI holds the tests back until it is ready.

  13. Which command runs a program inside a container that is already running?

    1. docker compose exec
    2. docker compose up
    3. docker compose logs
    4. docker compose ps
    Answer

    A. exec runs a command in a running container, for example psql. B is tempting, but up starts containers; it does not run extra programs inside them.

  14. Is it true that docker compose down, without -v, keeps the data stored in named volumes?

    Answer

    Yes, true. down removes the containers only. Adding -v also deletes the volumes, and with them all the data.

  15. How is a database service container in CI similar to Docker Compose on your PC?

    Answer

    Both start the same image with the same settings, port and healthcheck next to your code. The tests connect the same way in both places, so they behave the same locally and in CI.

  16. Each instruction in a Dockerfile adds one image _____.

    Answer

    Layer. An image is a stack of layers. Docker caches them, so a rebuild only redoes the layers that changed.

🔎Things worth noticing

  • If the volume already existed before the init script was added, habits_test was never created. The fix is docker compose down -v then up -d (this also wipes the dev data).
  • CI does not use the init script: it creates habits_test directly with POSTGRES_DB. Two routes, same result.
  • The password habits is fine for a local box, but production must use a real secret.
